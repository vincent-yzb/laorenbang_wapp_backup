# 微信身份字段迁移

本迁移只向 users、angels 新增可空的唯一 wechatOpenId 字段及索引，不改写、删除或合并任何已有账号。本迁移已在全新本地 PostgreSQL 隔离库中验证；没有连接、修改或迁移任何现有业务数据库。

仓库现包含 `20260120_baseline`，它由仓库中添加 wechatOpenId 之前的 Prisma schema 重建，**不是任何已上线数据库的经过验证的结构快照**。全新的隔离空数据库可以按顺序部署该基线与本增量迁移。已有非空业务数据库不可直接运行整套迁移，也不能未经核对就把基线标记为已应用：发布人员应先备份，在独立副本上逐表、字段、索引、约束与基线 SQL 做 schema diff；只有确认一致并评审后才能采用 baseline resolve 流程，或由有权限人员手工受控执行增量 SQL。若有差异，先制定专门迁移方案。应用新代码前完成该发布步骤，并重新生成 Prisma Client。数据库尚未迁移时，新微信登录会失败，不会退回测试账号。

旧代码仅保存 openid 的后 8 位，且微信接口失败时使用共享开发身份。完整 openid 无法从这些旧数据恢复，不能自动回填或按后 8 位认领账号。历史微信用户需要通过受信任的账号恢复流程验证旧账号所有权后重新绑定；在该流程完成前，新微信登录会创建独立账号，不会自动获得旧账号数据。不要以重复手机号为由自动合并账号。

新账号以完整 wechatOpenId 查找。为兼容 phone 非空字段，未绑定手机时使用 wx_ 加完整 openid 的 SHA-256 值作占位；该占位不用于身份匹配。用户绑定真实手机号后，wechatOpenId 保持不变。
