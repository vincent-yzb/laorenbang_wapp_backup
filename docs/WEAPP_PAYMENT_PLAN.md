# 微信支付优先开发计划

更新：2026-10-08。范围仅微信小程序与 `laorenbang_wapp_backend/`。本文件接续 P0，不表示真实商户交易已验收。

## 目标与当前条件

用户将支付列为最高优先级，现有企业或个体工商户营业执照，尚无微信支付商户号。开发、隔离测试与默认关闭的测试环境发布可以并行推进；真实收款和出款必须在商户申请、AppID 绑定、接口权限与私密配置完成后验收。手机号授权暂缓。

保持服务后付款与 20% 平台佣金。子女付款到运营主体的微信支付商户账户；平台内部账目记录天使 80% 收入。内部余额不表示资金已经向天使转账。该实现是普通商户收款加独立商家转账，不是微信分账产品；正式运营前须由实际运营主体确认业务和结算模式适用且获得相应权限。

## 实施与门槛

| 顺序 | 内容 | 验收要求 |
| --- | --- | --- |
| 1 | 商户 APIv3 网关、私钥签名、微信支付公钥验签、通知解密 | 离线 RSA/AES 测试；错误应答也验签；默认关闭且零资金调用 |
| 2 | 持久支付单、稳定商户单号、服务后付款、通知与查单补偿 | 同单并发仅一次预下单；未知结果不换单；金额/币种/主体/付款人核验；只记一次收入 |
| 3 | 金额增量迁移、精确分账、冻结余额、可提现余额 | PostgreSQL 真事务与并发测试；旧余额与模拟收入不可真实提现；无损保留 Float 兼容字段 |
| 4 | 全额退款申请与独立运营审核 | 受理不显示已退款；核验成功才冲回天使收入；未知或异常保留冻结与查单 |
| 5 | 微信钱包提现、独立审核、用户确认收款 | REQUESTED/WAIT_USER_CONFIRM/SUCCESS 分开；仅服务端核验 SUCCESS 扣余额；稳定请求标识防重复提现 |
| 6 | 小程序支付与资金状态页面 | SDK 结果只触发服务端查单；取消也核实；有界轮询；未决状态不误报完成 |
| 7 | 隔离测试环境更新与商户真机验收 | 保留用户现有数据与旧服务；增量迁移；默认关闭发布；商户配置后按小额清单逐项验收 |

## 核心账务规则

- 所有新资金计算使用 BIGINT 分，JSON 输出十进制字符串；向微信发送金额前校验为安全整数。旧元 Float 仅作兼容镜像。
- 天使份额为 `(总分 × 80 + 50) / 100` 的整数除法，平台份额等于总分减天使份额，二者严格相等于总分。
- `可提现 = 总余额 − 冻结余额 − 不可提现余额`。冻结属于总余额的一部分。数据库约束拒绝负数或重复冻结超过余额。
- 迁移前余额成为不可变期初锚点，并全部标记不可提现；历史收入回填金额但不再重复入账。旧已支付订单标记 `LEGACY_UNVERIFIED`，不伪造微信交易号。
- 新收入、退款、提现有唯一账目键。账务核对：期初余额加所有非 `LEGACY` 账目应等于当前余额。
- 实际提现只接受完整微信身份与已核验真实收入。首版每笔小于 2000 元；大额所需收款姓名核验与敏感字段加密另行开发。
- 未知资金结果沿用原单号查询，不自动换单重试。退款异常进入人工处理。前端、运营入口和查询动作均不得假定 SDK 成功等于到账。

## 外部配置与发布策略

详见 [商户开通与验收](WECHAT_PAY_ACTIVATION.md)。私钥与密钥只存服务端私有环境。`WECHAT_PAY_ENABLED` 与 `WECHAT_TRANSFER_ENABLED` 初始为 `false`，模拟支付在 production 永远关闭。独立运营审批凭证不下发客户端，用户 JWT 不能替代审批权限。

当前 Render free 环境只用于内测。正式支付通知需要持续可用的 HTTPS 服务；免费实例休眠、免费测试数据库到期和未完成微信合法域名配置均不满足正式收款上线条件。升级资源需另行确认成本，不能在开发中自动升级。
