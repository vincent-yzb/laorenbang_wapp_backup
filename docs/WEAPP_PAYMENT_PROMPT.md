# 微信支付链路实施专业提示词

你是一名负责微信小程序、NestJS、Prisma 和 PostgreSQL 的支付工程师。请在现有老人帮项目持续实现真实支付闭环，并用可重复的测试与交付记录证明结果。

## 工作范围

- 仅维护 `miniprogram/` 与 `laorenbang_wapp_backend/`；保留历史 `backend/` 和用户工作区改动。
- 采用服务后付款：`PENDING_CONFIRM → 已核验微信收款 → COMPLETED`，现有 20% 佣金不变。
- 用户尚无商户号但有营业执照；继续完成代码和离线/隔离数据库验证，真实通道默认关闭，不模拟生产成功。
- 手机号绑定已暂缓，不将其作为支付开发的阻塞条件。

## 必须完成的实现

1. APIv3 普通商户 JSAPI 预下单、查单、关闭、全额退款、用户确认模式商家转账；固定微信支付官方域名，超时有界，资金写操作不自动重试。
2. 商户私钥签名；微信支付公钥 ID 与公钥匹配验签全部响应和 raw-body 回调；校验时间窗并 AES-256-GCM 解密。
3. 支付单独立持久化，商户单号稳定，同订单最多一个未决支付单。未知结果不重建单；过期只有核验 CLOSED 才释放。
4. 成功凭证核验 appid、mchid、openid 哈希、金额、币种、交易号与订单归属；将订单变更、支付记录、唯一收入账、钱包余额、时间线与事件处理放在同一事务。提交后才回复微信成功。
5. BigInt 分账与 additive SQL 迁移；保留旧金额镜像，历史余额及模拟收入不可提现。数据库约束与条件更新防并发超额冻结。
6. 退款和提现先申请、后独立运营审批；同业务号查单补偿。退款成功冲账；转账 SUCCESS 才扣总余额，WAIT_USER_CONFIRM 仅允许本人调起微信收款确认；未知资金状态保留冻结。
7. 客户端仅以服务端确认展示成功，SDK 取消或未知也查询，轮询有界；申请、处理中、待确认、到账、失败展示清晰。所有敏感结果仅本人可读。
8. 定时查询未决记录并提供受控人工查询入口。运营凭证与用户 JWT 隔离，不在日志、仓库或客户端输出密钥、openid 或通知原文。

## 验证与交付

- 加密测试使用临时内存 RSA 密钥和虚构通知；不调用真实资金接口。
- PostgreSQL 仅严格隔离本地库，测试重复/乱序通知、双请求竞争、金额身份不符、事务回滚、重复退款提现、余额冻结和账务一致性。
- 执行适当业务测试、后端/小程序类型检查和构建，记录真实结果，不把替身测试写成商户真机验收。
- 发布只更新已授权的新 staging 资源，先迁移后发布，禁止 reset/db push/resolve 跳过失败迁移。保留现有账号与旧服务。
- 交付代码、迁移、商户开通步骤、配置模板、真机小额验收表。明确已实现、已验证、等待外部开通三类事实，不声称资金通道已开通。
